# Nexowire Stack elevated Task launcher: protected cutover acceptance contract

Read-only inspection of **live production Naveax** on 2026-10-11 confirmed the existing scheduled task `\Nexowire Stack` is Running at Highest interactive privilege. The Task action uses unqualified `powershell.exe` instead of a fixed trusted System32 interpreter and runs `C:\Users\navea\AppData\Local\NexowireStack\run-stack.ps1`, outside the previously audited `C:\ProgramData\NexowireStack` dependency tree. The known launcher and four of its immediate ancestors have non-protected ALLOW write ACEs (five of six checked nodes total). It does not include `-NonInteractive`. The Task's actual full arguments were **not** emitted, and no script was invoked through the Task.

This means merely hardening the ProgramData JavaScript modules would **not** close [P0 #271](https://github.com/Naveax/Nexowire/issues/271). The actual elevated entrypoint and its launcher-parent directory chain are independent exposure paths.

The source-only strict `verifyPrivilegedStackTaskSnapshot` provides a prospective owner-review cutover policy, NOT permission to modify an existing task. It requires exactly ONE action, one Logon trigger for the correctly verified current owner SID, Running+Highest+Interactive, exact full System32 PowerShell path, exact security flags (`-NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass`), exact future protected `-File "C:\ProgramData\NexowireStack\run-stack.ps1"` and matching working directory. A presently observed unqualified interpreter or per-user AppData launcher fails closed. The expected future path is a **candidate for independent owner/security review**, not proof that any safe installer or cutover is ready.

The direct `auditPrivilegedStackSource` entrypoint chain now also revalidates every source component after its ACL check and rechecks the earlier ancestors before returning. It compares directory child names as well as identity and modification metadata; this detects observable mid-scan file replacement and unreviewed child creation, without claiming an atomic filesystem or currently running code attestation. Its testable snapshot-only helper is not an authorized source of production trust.

The separate `auditProtectedPrivilegedStackLauncherReadOnly` would validate the protected *future* launcher and Stack root ACLs, reject symlink and hardlink launcher aliases and require the entire dependency tree's ACL inventory. It also checks launcher/root identity, modification metadata, and root child names immediately after each ACL check and again after completing the dependency inventory. Any observable mid-audit change fails closed. Its injectable `inspectProtectedStackLauncherSnapshotOnly` helper is **test-only** and does not confer trusted OS authority. It executes no Windows Task command, installs nothing, and explicitly returns `taskAclVerified:false`, `runningProcessAttested:false`, `remoteActuationAuthorized:false`. A plain JSON task snapshot is not a trustworthy collector by itself.

The bounded full-tree source inventory additionally performs fail-closed change detection: it rechecks file/directory identity, modification metadata, and directory-child names after each ACL read, after directory enumeration, and across previously visited paths at the end of the scan. This rejects observed source replacements or content changes during the read-only audit. It does **not** make filesystem inspection atomic, prevent changes after the final sample, prove effective Windows permissions in all contexts, or certify a live executing process. A protected install/runtime boundary and independent production acceptance are still required.

**Remaining acceptance criteria before any owner-approved cutover:** independently protect the target installer and its full dependency closure; verify true executable publisher/source bytes and the Task DACL; prove the exact Task action/trigger/working directory/owner SID from protected local collection; arrange safe recovery/rollback before moving or re-pointing tasks; verify there are no untrusted dynamic imports, externally writable junctions or hardlinks; retest existing active process and updated ACLs without downtime. This code adds none of those installation or mutation steps. Cloudflare Worker, D1, existing Windows Stack, Guardian and Agent production state remain unchanged.

Real Admin Bridge privileged ON/OFF must continue to fail closed while P0 #271 remains open.
