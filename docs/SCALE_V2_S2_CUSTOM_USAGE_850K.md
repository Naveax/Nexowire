**15 October 2026 | OWNER REQUEST | NOT LIVE.** This is a standalone, disabled proposal for an *existing owner-controlled self-hosted Hub*. It is independent of pending Z2 Tailscale PR #510 and has no Cloudflare migrations, paid billing, live Agent/Hub/Broker restart, entitlement write API or Worker import.

## Product design

- **Free:** 1,000 logical Nexowire tool invocations/day (FUTURE/OFF).
- **Plus:** 5,000/day (FUTURE/OFF).
- **Pro:** 10,000/day (FUTURE/OFF).
- **Custom Usage:** user can request a whole-number allowance between **100 and 850,000 logical Nexowire tool invocations/day**, inclusive, **but** the owner server must independently verify the subscribed, versioned and paid entitlement before issuing an authorization. A client-selected numeric field alone never raises the cap. Price model, refund/upgrade/proration and abuse rules are not implemented.
- All plans should have the same Nexowire tool feature catalogue. Device ownership/Agent consent, per-command scopes, Root/Broker approval, availability, platform app permissions, account revocation and operator cost protection are **separate uniform safety mechanisms**, not sold features. The existing `feature-not-in-plan` policy is **not removed by this PR**; a distinct security-reviewed migration is necessary.
- **One logical tool invocation = one quota unit**. The active legacy production code still charges Free 1,000 **weighted credits/month** (normal 1x, special skills 5x) and the verified owner GitHub identity may receive `monthlyCredits:null`. There is NO new daily plan activated by this PR.

## Transport cap and the hidden catch

Official [OpenAI Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) default: **600 MCP requests/minute** (10/s sustained), **per tunnel ID + calling application ID across all MCP channels**; when app ID is absent, shared by tunnel+user. Running a second client does **not** multiply this capacity. This default is **not** a general ChatGPT Plus plan entitlement, not 600/min per Nexowire user sharing one tunnel and not an Enterprise guarantee. OpenAI Support must review any limit changes. Other transports have separate restrictions.

**864,000 requests/24h theoretical**, so 850,000/day demands `850,000 / 1440 = 590.28` requests/minute on average = **98.38%** of the theoretical daily tunnel maximum. At 600/minute uninterrupted, 850,000 takes **23h 36m 40s**, leaving **23m 20s** worth of theoretical peak-rate slack across the whole day. Handshakes, retries, discovery, metadata and shared users can consume the same provider request budget. **850k is an advertised configurable Nexowire allowance, NOT a guarantee users can consume it.**

Current official custom MCP full read/write support is ChatGPT Business / Enterprise / Edu on web, with Pro more limited to read/fetch; **do not assume ChatGPT Plus users can invoke every tool or that Enterprise automatically lifts the tunnel rate.** Source: https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt

## Prototype implementation

- `src/product/custom-usage-owner-meter-proposal.ts`: pure trusted tier resolution and **single-writer transactional SQLite DEV meter**. It requires a first-party asserted `entitlementVerified`, server-derived canonical quota-subject ID, immutable invocation ID and server-verified transport scope (tunnel+calling app), plus trusted UTC clock.
- `test/fixtures/scale-v2-custom-usage-selfhosted-dev.sql`: owner-side daily counters, globally persistent per-subject replay ledger, transport-scope timestamp tracking and indexed 60-second rolling transport admission window. The code starts `BEGIN IMMEDIATE`, rechecks replay, entitlement, the exact daily allowance and shared rolling scope, writes everything together, and commits; any database error fails closed. Downgrade below used allowance prevents new requests. Raising the limit does not retroactively execute denied requests or restore revoked authorizations.
- A rolling 60-second window is used, not a UTC calendar-minute reset. Distinct users sharing a tunnel/application share a single 600-per-60-second admitted-tool-call budget. Separate authorized scopes remain isolated, but MUST NOT be generated by untrusted MCP JSON to multiply a provider allowance.
- The replay rows are intentionally **not pruned** during this proof. A large hot tenant incurs substantial disk and write costs; long-term retention, short-lived signed invocation issuance/freshness, compaction, tenant sharding and rollback need real capacity acceptance before rollout.
- The meter tracks **successful admitted logical tool calls only**, not **all** provider MCP transport requests. A separate ingress-wide transport limiter must count discovery/auth/denied/retries and obey the real platform's shared rate and deadline. Without that additional guard, this module by itself CANNOT guarantee compliance with OpenAI's 600/min provider quota.

## Verified staging tests

`node --test --import tsx test/custom-usage-owner-meter-staging.test.ts`: 13/13 Windows Node SQLite test cases PASS, including 100 and 850,000 contract bounds, upgrading/downgrading, 600th admitted and 601st denied with 60s recovery, shared transport scope across three accounts, separate authenticated scopes, UTC midnight rolling-minute boundary, replay across date/plan changes, unverified entitlement fail closed, clock rewind denial, synthetic near-850k counter rollover, two instances over one SQLite writer, invalid request and missing DB schema. **The 850k boundary is counter-seeded**, not 850,000 actual completed network calls or a throughput benchmark.

## NO-GO / implementation gates

1. Real owner-operated trusted admission source and authenticated account/tunnel/app identities. Never trust a user-editable local SQLite file for metered subscriptions, and never let an MCP argument set `entitlementVerified` or `transportScope`.
2. Durable payment/order verification, plan-version records, upgrade/refund/UTC rollover semantics, replay ledger retention and backfill from legacy monthly credits.
3. Per-tunnel/application ingress-wide 600 rolling rate limits for **ALL provider requests**, platform metrics including discovery/retries, queue backpressure, 10 MiB payload and 120s provider deadlines. Distinguish provider limits from Nexowire allowances and from ChatGPT workspace entitlements.
4. Real 1/100/850k tool/day load tests over approved free transport on isolated PC hardware; stress 600/min for 24h without affecting a real user desktop. Benchmark SQLite lock contention, disk usage, p95/p99, retries, dropped/unacknowledged commits and cost. No guarantee 850k is sustainable.
5. Keep active legacy Free monthly plan, owner exception, Agent/Hub/Broker, DNS/Funnel, Cloudflare D1/Workers, billing and daily quotas **unchanged** until separate owner-approved canary/rollback and fully successful GitHub CI.
