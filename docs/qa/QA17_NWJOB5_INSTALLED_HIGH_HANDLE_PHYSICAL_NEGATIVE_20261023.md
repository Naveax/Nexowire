Run **only after** independent authorisation for an opt-in *isolated Windows staging environment* with a real first-party signed protected HIGH Broker/guardian. 1. **Independent preconditions / provenance.** A trusted protected native verifier must establish, using retained native image and parent directory handles, the installed Broker and guardian image SHA-256, pinned publisher/cert chain, protected effective DACL, volume serial/GUID and **FileID**. 2. **Two different attacker contexts.** Independently create and verify (A) a genuinely separate restricted low-integrity token or AppContainer (OS token SID, integrity RID, restricted SIDs or AppContainer SID/capabilities), and (B) a same-account **unelevated medium-integrity** process, which detects the same-user duplication exposure evidenced by #756. 3. **Native HANDLE negative.** With the exact Broker and guardian still live and independently PID+FILETIME matched, each attacker calls `OpenProcess(PROCESS_DUP_HANDLE, FALSE, actualPid)`. **Expected** for both targets and both attacker identities: kernel `ERROR_ACCESS_DENIED = 5`; no acquired duplication-capable process HANDLE. If any handle is unexpectedly obtained, attempt no destructive effect: record **FAIL**, independently check whether `DuplicateHandle` could retain the exact Job object as a query HANDLE, close all test-owned handles immediately and quarantine acceptance. `ERROR_INVALID_PARAMETER`, dead PID, other identity, timeout, API not callable or `DENIED` claim string are **INCONCLUSIVE/FAIL**, not native denial. Independently verify process/Job DACL effective rights: a printed deny ACE is not proof of effective access denial.

After **verified** stop, inspect original Job/root and descendants by PID+creation FILETIME and Job accounting: no surviving task process, no unauthorised retained duplicate/query HANDLE. The invocation of `requestWindowsJobStop()` or an `exited` status is not termination proof. Stream integrity from #829 is a **separate independent source-level gate**, not a security grant or HANDLE-lifetime witness.
5. **Fail closed on other claimed task sandbox dimensions.** A successful HANDLE negative authorises only the narrow process/Job HANDLE boundary.
