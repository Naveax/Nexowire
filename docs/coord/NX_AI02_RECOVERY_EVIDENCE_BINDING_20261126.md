## Implemented source-only commitment codec

New deterministic SHA-256 binding with separate transaction and evidence domains and uint32 big-endian byte-length framing, exact field order in source. Stable independently observed transaction identity is NOT a fresh challenge/request nonce, and must be canonical and scoped to installation/device and immutable recovery transaction by the independent owner-side authority. The evidence commitment covers purpose, transaction digest, scope, owner approval, SQLite continuity, writer fence, actual recovery task absence, activation fence, signed runtime manifest, release anchor, held runtime identity, held helper identity, and terminal receipt (required for coordinated uninstall). All inputs are exact opaque bytes, not trusted facts merely because nonempty. No input canonicalization, new signature verifier, positive authorization, private key, OS effect or provider configuration. A changed evidence packet changes bindingSha256 but never the stable transaction digest. Existing ledger's reserve/seal/consume CAS therefore prevents reissue of that exact transaction or consumption with another binding. A coordinated uninstall must have a separately approved immutable transaction identity linked to actual prior terminal recovery receipt, not reuse a spent rollback transaction or create a retry nonce to bypass it.

This codec is not wired to production effects. The independent service must verify signatures, provenance, freshness, canonical encoding and cross-packet scope first; require actual observation and held lease continuity before signing/consuming. Freeze the approved evidence bytes; revalidate live prerequisites using the same held lease at consumption. Do not silently substitute a refreshed commitment or create a new transaction after denial. Signing must include exact authority/store, authorization ID, device, transaction and binding digests, timestamps and domain. Ledger must durably seal exact envelope before publication and consume it before any separately authorized effect. Consumption is not a terminal effect receipt. Unknown or lost ACK burns the use; no automatic replay. No guarantee against rollback of the authority storage itself without independent monotonic lineage. Do not place the authority database or signing custody in the same VM/checkpoint rollback domain.
