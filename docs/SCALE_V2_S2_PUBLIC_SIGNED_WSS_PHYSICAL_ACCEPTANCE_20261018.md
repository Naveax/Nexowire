# Scale v2 S2: physically verified public signed WSS owner quota RPC (DEV acceptance)

**Observed 2026-10-18 on two physical Windows PCs: Work PC (operator/owner fixture) and Naveax (device-held ephemeral signing key). No production rollout.**

## Actual physical acceptance

- Work PC ran a Node owner-host `ProposedTrustedOwnerQuotaAuthority`, strict signed owner RPC and `startProposedOwnerQuotaOutboundWsHub`, bound **only to 127.0.0.1** with a synthetic free-standing account/device, random bearer and 100-read test allowance in an in-memory SQLite DB. No Agent or native command can be invoked by this fixture.
- The official `cloudflared 2026.10.1` binary was obtained with verified release SHA-256 `4d2490e74082c5d48dbfedaf92576fa5bd1702379ab88eb7faa0cfbe8dc891b6` and valid Windows Authenticode. A **temporary account-less Quick Tunnel** connected to the isolated loopback owner WS.
- On Naveax, a **separate transient Ed25519 private key was generated locally**. Only its public SPKI was sent to the owner fixture. A signed canonical RPC frame travelled through a public `wss://*.trycloudflare.com/internal/owner-quota/v1/outbound` endpoint. The client independently verified public TLS 1.3 CA chain, inspected the leaf SPKI fingerprint, and used Node's CA-validated WebSocket connection.
- **PASS:** public Cloudflare WSS handshake from Naveax, signed `reserve` -> HTTP 200 / `decision.status=reserved` / `authorizesToolExecution=false`, identical signed nonce with a new request ID -> HTTP 409. The real owner RPC denied replay without silently repeating the tool. The signed frame and account were synthetic and never reached live Hub/Broker.
- Managed owner server and tunnel stopped. Work PC loopback port verified closed. Naveax transient private key and client script removed; Work PC synthetic bearer readiness file and temporary scripts removed. No tunnel service installation, permanent firewall/DNS, Free quota, checkout or live Agent restart occurred.

**Limits of this result:** both physical computers may share an ISP/LAN, even though the path traversed real Cloudflare public infrastructure. This is NOT a test of two different consumer ISP paths. Quick Tunnel is temporary/non-SLA and does not establish named production DNS. The original successful Node client validated CA/TLS and **observed** SPKI but did not enforce independently provisioned SPKI at the WebSocket handshake; the reusable client fixture below adds an independently supplied SPKI preflight, which is not a replacement for a production pinned TLS agent. Actual first-party OAuth, continuous server-side revocation of live in-flight operations, operator-signed enrollment distribution and dynamic scaling remain outstanding.

## New staging owner trust-state adapter

`src/product/owner-public-wss-owner-state-reader-proposal.ts` creates an owner-host-only **fresh** SQLite authority reader. A single coherent joined read checks account/session generation, device ownership/enabled, device Ed25519 public key (pinned digest), revision and revocation floor, and trusted time. It integrates with the existing signed enrollment lease which invalidates permanently when an owner setting is revoked or unreadable. Tests verify session rollback, profile disable/revision increases, owner transfer, account/device shutdown, device key rotation and trusted clock rollback.

This is still a local staging seam, not a production remote authenticated control-plane reader. The initial browser-based Cloudflare Dashboard access attempt met a bot-check security page; no bypass or login mutation attempted. Production named Tunnel provisioning depends on an authorized interactive account/domain flow. Other gating requirements: authenticated OAuth code/token issuer wired to real dispatcher, device private key initial enrollment and secure storage, active Broker execution grants, true off-LAN two-network testing, real 100+ sessions, 600/min enforced ingress, 24h 850k/day tool completion and actual ISP/Cloudflare cost.
