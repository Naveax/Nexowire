# Nexowire v1.0.9-exp0-danger: OFFLINE DANGER LAB

**This is NOT an unprotected remote-administrator build.** The word danger is an intentionally visible testing label. No Windows admin boundary, Broker authentication, owner identity checks, UAC, DPAPI, STOP/revoke or remote-control authorization is disabled.

## What differs from v1.0.9-exp.0

- Separate prerelease semantic version `1.0.9-exp0-danger`, tag `v1.0.9-exp0-danger`.
- Dedicated CLI sandbox: `nexowire danger-lab status` and `nexowire danger-lab simulate <capability> [text]`.
- The model accepts **arbitrary capability names** and returns `SIMULATED_ALLOW`, but it NEVER performs a host action, opens a listener, calls the Broker, invokes PowerShell, accesses the filesystem, or enrolls CORE.
- Simulated requests are fingerprinted with SHA-256. Raw payloads (including test secrets) are not returned.
- Distinct `Nexowire Danger Lab.lnk` Start Menu shortcut and no automatic stable-channel updater registration.
- The original stable `v1.0.8` and already published `v1.0.9-exp.0` stay unchanged.

## Explicit limitations

Real Nexowire operations still use existing owner authorization, Windows UAC and Broker checks. This version does **not** deliver unlimited real CORE, SYSTEM Hub takeover, unrestricted remote PowerShell, anonymous remote filesystem access or a bypass for physical consent. The underlying normal runtime is not fully tested on every Windows host. **Do not expose management services to the public Internet.**

## Test locally without changing Windows privileges

```powershell
nexowire danger-lab status
nexowire danger-lab simulate shell.powershell Get-Process
```

The output is a mock authorization decision, not command results. The command is not executed.

This build must only be distributed after its exact source SHA, CI checks, separate Windows bundle, versioned manifest and SHA256SUMS have been checked. It must never be labeled fully CORE-enabled or production safe.
