# Nexowire v1.0.8 — unreleased candidate

Target: reliable Windows startup and a simpler first installation. This file is
candidate documentation, not a published release or evidence of a device update.
The latest public stable version is v1.0.7.

## Included source work

- **WAL reuse / #974:** #957 recognizes SQLite's committed current-generation
  prefix followed by retained prior-generation allocation. Both WAL-index header
  copies, frame checksums, commit boundary, salts and file stability are checked
  before SQLite opens the journal. Ordinary valid reuse requires no manual repair.
- **Restart integrity:** a disposable SQLite-generated regression reproduces the
  reported geometry: 709 current frames, 295 retained frames and 473 commit frames.
  The actual journal contains 1,307 generated operation records. Eight fresh
  journal processes preserve every field, retain the WAL-only UNKNOWN tombstone
  and refuse all previously used request UUIDs. Damage remains rejected without
  rewriting any journal file. This is a synthetic dataset with authentic SQLite
  behavior; it is not a copy of the NAVEAX journal or a real Windows reboot.
  The actual Agent CLI also starts three times against an isolated local test
  Hub, preserving its generated identity; damaged WAL produces three denied
  Agent starts, an accurate diagnostic and unchanged journal bytes.
- **Startup diagnosis:** `agent status` and `agent doctor` expose the last bounded
  local initialization diagnostic. Three consecutive failures mark a restart
  loop. Error text, tokens, journal records, endpoints and paths are not stored.
  Successful initialization clears the streak, without claiming an authenticated
  connection or CORE authority. Failure to save diagnostics never suppresses the
  original startup failure. New Windows Agent task definitions use a hidden
  PowerShell window; retry, single-instance, battery and UPS settings are kept.
- **Power / #972:** Native Agent tasks continue on battery/UPS power and may start
  while on battery, with the existing single-instance and restart behavior.
- **Update acknowledgement:** the v1.0.8 user updater requires a fresh per-cutover
  nonce, matching Agent PID/version, exact candidate Node/CLI paths and successful
  local initialization across consecutive process observations. A transient Node
  PID or a previous startup file is insufficient. `agentStartupVerified` refers
  only to local startup; `activeConnectionVerified` remains false. Profile-secret
  resolution and independent Hub/device connectivity checks remain separate.
- **Update rollback:** only versioned launcher references and the startup nonce
  are edited. Unique launcher backups are pinned and rechecked with SHA-256.
  Failed stop/restore/restart cannot report a successful rollback; the status is
  `rollback_failed`, with current runtime version `unknown`. Disabled Native
  Agent tasks remain disabled. The helper never resets or restores the journal,
  identity or credentials. Its PowerShell executable and module environment are
  pinned to inbox Windows paths.
- **First PC installation / #971:** Windows instructions and a ready ChatGPT
  installation prompt cover a PC without Nexowire, Node or npm. The bootstrap
  verifies the public payload hash and supports Unicode paths and native Shell
  Links. The existing public bootstrap still intentionally downloads the actual
  published v1.0.7 payload; update the canonical links and checksum files only
  after an authorized v1.0.8 artifact exists.
- **Account quota / #973:** verified GitHub identity uses the reviewed scoped
  account quota change; unrelated signup and billing boundaries remain enforced.

The source batch is [Draft #978](https://github.com/Naveax/Nexowire/pull/978).
Source branches and their PRs are preserved. This batch does not silently include
the separate CORE authority, enrollment, Broker or sandbox Draft chains.

## Automatic startup behavior

Valid recycled WAL opens automatically through the normal SQLite path. No
checkpoint, backup swap, database rename or identity reset is needed. This fixes
the classification bug instead of periodically repairing valid files.

Genuine checksum/salt damage, torn frames or inconsistent index evidence still
block journal initialization and mutations. The Agent records a bounded failure
diagnostic when possible, while leaving DB/WAL/SHM bytes intact. Reviewed recovery
must preserve UUIDs, terminal records and UNKNOWN tombstones. Never retry a
previous mutation because its acknowledgement or outcome is unknown.

The informational snapshot is normally
`~/.nexowire/native-agent/startup-diagnostic.json`; with a configured custom
journal it is under `native-agent/` beside that journal. It is not a trust source.
`local-state-ready`, Scheduled Task `Running` and a successful diagnostic read do
not prove an active authenticated Hub connection or physical CORE acceptance.

The fresh update acknowledgement ships with the new updater; it does not
retroactively replace the helper already installed in v1.0.7. The first upgrade
from v1.0.7 still needs an authorized, verified successor artifact and independent
post-update/restart acceptance. Do not treat the old updater's process-only
`succeeded` record as proof that the new Agent initialized or connected.

## Release gates

- CI runs the incident-shaped reuse, forced process termination, clean restart,
  replay and damage regressions on Linux Node 22/24 and Windows Node 24.
- Release Readiness extracts the new Windows ZIP and repeats those regressions
  with **that payload's compiled journal modules and bundled Node executable**.
  It does not substitute the runner's Node, mock the SQLite engine or install a
  task on a live device. The fixtures never run an operation callback.
- The Windows cutover tests execute the generated PowerShell script against
  disposable profiles, real SQLite DB/WAL/SHM files with 1,307 generated records,
  and identity/credential byte canaries. All Task/CIM commands and startup records
  in that fixture are stubs. Stale/missing/malformed records, incorrect nonce/PID/
  version/executable, disappearing/duplicate processes, false connectivity/CORE
  claims, disabled tasks and rollback failures must be rejected without modifying
  journal or credential bytes. These are source tests, not physical rollout or
  DPAPI acceptance; real Agent CLI tests separately check emitted PID/nonce data.
- First installation, corrupt-download rejection, Unicode launch, version,
  package, metadata and checksum checks must also pass on the exact candidate.
- Before closing #974: review/merge the source, publish an authorized verifiable
  successor, preserve identity/credentials/journal through update, then verify
  repeated real Windows reboot and Agent task restart on an authorized canary.
  Confirm every operation row and UNKNOWN tombstone survives without manual
  maintenance. Those physical acceptance steps have not been performed here.
- Keep rollback from reintroducing an older journal or replaying an operation.
  Source CI and a temporary CI extraction are not proof of an installed publisher
  signature, anti-rollback deployment, external CAS or protected Windows token.

CORE production acceptance remains **NO-GO** until its separate real provider,
Broker/token/ACL, physical enrollment and revoke/restart acceptance gates pass.
No release publication, production deployment, main merge or device change is
authorized by this candidate work alone.
