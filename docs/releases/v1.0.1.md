# Nexowire v1.0.1

Nexowire v1.0.1 focuses on making the hosted Windows connection path usable by normal end users without exposing operator plumbing.

## User-facing changes

- Windows users can open `Nexowire-Setup.cmd` from the GitHub Release.
- No preinstalled Node.js/npm is required.
- No administrator elevation is required for the normal install.
- Setup installs a versioned runtime under the current user's LocalAppData, creates a Start Menu shortcut, and launches Nexowire without a visible terminal.
- Normal connection is reduced to: sign in if needed, then press **BAĞLA**.
- The production control-plane endpoint is built in. Normal users do not enter Hub URLs, bearer tokens, Tailscale addresses, capability lists, or per-tool access settings.
- Physical-console control remains an explicit exceptional override rather than part of routine onboarding.

## Reliability and release changes

- Re-pairing an existing device works even when the account's device limit is already full.
- The Windows payload bundles a checksum-verified official Node runtime and the Node distribution license.
- Windows setup and payload checksums are published with the release.
- Tagged releases generate provenance attestations for the Windows setup and payload alongside the existing canonical package/SBOM evidence.
- The release authorization path now relies on the tag push to trigger Release Readiness exactly once; it no longer dispatches a duplicate tag-scoped workflow.

The existing self-host/operator CLI and canonical npm tarball release artifact remain available. npm publication remains disabled.
