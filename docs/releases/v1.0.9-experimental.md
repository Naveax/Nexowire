## Non-destructive candidate checks

Run only inside a separate source worktree:

```powershell
npm ci
npm run typecheck
npm run build
node --import tsx scripts/check-release-package.ts
node --test test/ci/v109-experimental-source-audit.test.mjs
node scripts/ci/v109-experimental-source-audit.mjs --json
powershell -NoProfile -File scripts/Read-Nexowire-V109CoreReadiness.ps1 -Json
```

The PowerShell preflight reads scheduled-task summary, loopback listener metadata,
and the available disk space on the user-profile and ProgramData volumes. It reports
an **advisory** 8 GiB recommended reserve for the planned physical SYSTEM cutover.
If a volume cannot be inspected, free space and reserve compliance are reported as
`null` / `UNKNOWN`, never falsely passed. Disk headroom is not evidence that
migration, SQLite state, protected credentials, or CORE authorization passed.
The preflight does not read secrets, run CORE enrollment, or change any process.
Do not use `core-console status` as a side-effect-free probe; its current source
calls an identity load-or-create routine.

## Before claiming full Work-PC CORE

1. Explicit owner-approved elevated Windows session and trusted protected runtime/task.
2. Authenticated elevated Broker effects with fresh operation-correlated readback.
3. Protected ProgramData state, real SYSTEM DPAPI and transactional SQLite cutover.
4. Owner-bound CORE grant, actual scoped operation, revocation, replay denial,
   crash/restart and rollback acceptance.
5. Real reboot and two-device/off-network recovery tests with independent evidence.

An experimental label permits unpolished functionality but does not grant arbitrary
remote users unbounded Windows administrator privileges. CORE remains owner-bound,
revocable and auditable even in preview builds.

## Publication rules

- `v1.0.9-exp.0` is an existing published GitHub **prerelease**, not a stable release. Do not republish or rewrite its immutable tag.
- A source-only candidate is not a validated Windows installer or full CORE release.
- Independently verify exact-head CI, candidate ZIP, hashes, signatures and rollback.
- A separate future prerelease requires explicit approval, a new tag and exact-source evidence; the existing `v1.0.9-exp.0` publication grants no stable authorization.
- Keep v1.0.8 as the authorized stable version.
- The preview installer uses a separate `Nexowire Experimental.lnk` shortcut and
  does **not** register the stable-channel hourly auto-update task. Normal
  stable installers keep their existing auto-update behavior.
- The versioned executable directory is separate, but user profile data and
  app identities can still be shared. Before testing on NAVEAX, back up any
  existing Nexowire state and do not replace a running production instance.
- No automatic Work-PC update, UAC bypass, public ingress or secret migration.
