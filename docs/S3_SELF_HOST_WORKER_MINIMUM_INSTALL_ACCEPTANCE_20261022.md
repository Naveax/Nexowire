### Deterministic aggregate decision (proposed contract, not implemented)

For a self-host coding-worker deployment decision, all `G00..G08` must be independently current, cryptographically pinned and tied to the **same** `ownerAccountId + workerDeviceId + signingKeySPKI + workerPrincipalSID + installTransactionId + ownerEpoch + grantGeneration + worktreeRoot` where relevant. No branch can convert source fixture status, OAuth principal, process Job or local DPAPI secret into `installAllowed:true`.

- If **any** hard identity/import/ACL/sandbox preflight is absent or false: `DENIED`; `workerInstallAllowed:false`, `workerDispatchAllowed:false`, `brokerElevated:false`.
- If authority, native effect or revoke ordering is **unknown after possible mutation**: `RECONCILE_REQUIRED`, with no retry, new requestId, rollback, key reuse or quota release until independently authenticated stop/effect state.
- Only after every required gate has **real** independent physical evidence may the future unprivileged worker installer be considered for an explicit owner-approved operation. It must not install a HIGH Broker. Even then, CORE remains disabled until **separate** #271/#551/#617 physical acceptance.

**Current decision:** `workerInstallAllowed:false`, `workerDispatchAllowed:false`, `brokerElevated:false`, `productionApproved:false`. This is a written gate, not a code path or hardware attestation.

## Ownership and sequencing

1. **#12 document/signature/rollback preflight first:** pin worker-only installer/rollback bytes, trust chain, file IDs, protected paths; don't install anything.
2. **#07/#13/#04 external enrollment + #03/#05 OS identity:** distinct non-exportable worker signer and low privilege token with source AND physical negatives. The OAuth principal is not a worker grant; Windows Job is not an OS sandbox.
3. **#01/#08/#587 journal/checkpoint/revoke:** independent durable CAS/UNKNOWN reconciliation, no side-effect replay or reused owner epoch/key after restart.
4. **#16 independently verify in disposable isolated physical environment** before product launch. **Only afterward** consider unprivileged self-host worker rollout. Optional ephemeral cloud runner is later and must use a separate key/owner enrollment and explicit billing consent.
