## Confirmed #08 source gap: cloned checkpoint read after external CAS

At exact #785, VerifiedTransferCheckpointAdapter.get() checked only owner/project/device and current CORE. It returned an existing valid checkpoint when handed a DIFFERENT transfer UUID with the same scope, or a transfer journal subsequently rolled back to MUTATION_UNKNOWN, or a local copy with forged durableCommitId. This can misattribute an old Artifact to a new transfer after the #781-style clone-by-identity pattern. Deterministic original #785 owner test became RED (Missing expected rejection).

Narrow fix: for a nonempty checkpoint require job COMPLETED + exact bytes, exactly one Artifact manifest bound to this specific producerOperationId==job.id, owner/project/device, SHA and length; then perform protected external final publication CAS readback against current job with valid fencing/requestId/epoch/SHA/durableCommitId and revalidate CORE. The producerOperationId check is also required on persist() before saving. A cloned job UUID yields JOB_CHECKPOINT_TRANSFER_MISMATCH; UNKNOWN yields JOB_NOT_VERIFIED; forged publication commit yields JOB_PUBLICATION_COMMIT_MISMATCH; unrelated manifest with identical bytes/SHA yields JOB_ARTIFACT_ATTESTATION_MISSING.
